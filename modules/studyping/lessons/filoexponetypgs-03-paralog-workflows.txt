### 2.3. Pipelines for paralog identification and handling



#### 2.3.1. HybPiper paralog retriever



Paralog sequences were recovered with `hybpiper paralog retriever` using default parameters, which identifies a gene as paralogous if multiple sequences more than 75% the length of the reference for that gene are recovered. HybPiper also produces a second paralog warning based on depth, where if the set of sequences assembled have a depth of greater than 1 across at least 75% of the reference length, the gene is identified as paralogous, even if individual sequences are less than 75% the reference length. However, this "paralog warning by depth" was not used as the script only flagged potentially paralogous genes but did not generate paralog sequences for downstream processing. The `hybpiper paralog stats` function was used to summarise and visualise the paralog recovery based on sequence length across all samples. As long as one sample has paralogous sequences recovered, the gene is identified as paralogous in the summary statistics provided by `hybpiper paralog stats`.

#### 2.3.2. CAPTUS



In CAPTUS, paralogs are recovered as part of the default pipeline during the `captus_assembly align` step. All sequences assigned to a gene are aligned and their similarity to the reference sequence was compared. Based on the default paralog handling parameters in CAPTUS (i.e., the `paralog_tolerance` parameter), when more than one sequence was assembled for the gene, the copy with the highest similarity and coverage with respect to the reference was chosen to be the main copy, while up to a total of five other sequences were kept and flagged as paralogs. A summary of the paralogs recovered was provided in the file `captus-assembly_align.paralogs.tsv`.

#### 2.3.3. Putative paralog detection



The Putative Paralog Detection Pipeline (PPD) identifies paralogs by using sequence similarity and the proportion of heterozygous sites. Trimmed reads were mapped back to their assembled sequences, and sequences with an excessively high rate of heterozygosity (> 5% by default) were attributed to assembly errors and removed. The remaining sequences were aligned and if heterozygous sites were shared across more than a certain percentage of samples, the gene was flagged as paralogous.

PPD was run for two different datasets: 1) the 25 *Sindora* clade samples (to allow comparison of paralogs flagged by the BLAST search against the *Sindora glabra* reference genome); and 2) the full dataset of 88 samples across the Detarioideae subfamily (to generate paralog counts for preparing paralog-excluded datasets, and trimmed alignments for subsequent phylogenetic tree construction).

Three values of the `bwa mem` $k$ parameter for read mapping in `Step2.sh` were used to test the impact on paralog identification. This corresponds to the minimum seed length for matches, and we used the recommended value of $k=100$, an intermediate value of $k=60$, and the smallest value of $k=19$, which is the default value for `bwa mem`.

Default values were followed for the subsequent steps of PPD, such that in step s2 sequences with more than 5% of heterozygous sites were removed, in step s6 alignment columns with more than 50% missing data were removed, and in step s7 alignments were further trimmed along a sliding window with parameters `-mi 15` and `-w 20`, where if more than 15 polymorphic sites exist within a sliding window of 20 bp, these polymorphic sites will be marked and removed with TrimAl. However, the number of polymorphic sites was adjusted to be higher than the original maximum of 4 (`-mi 4`) used for single genera. Our datasets of the 25 *Sindora* clade samples and 88 samples across the Detarioideae subfamily were expected to have more variation because they cover greater phylogenetic breadth, so to avoid polymorphic regions from true intergeneric variation from being removed, we increased the value of the `-mi` parameter.

For step s8, genes were identified as paralogous if there were heterozygous sites shared across more than 50% of the samples (the default value, which was used for the set of 25 *Sindora* clade samples). However, a reduced cutoff value of 14%, corresponding to half the size of the *Sindora* clade (13 samples), was used for the full set of 88 samples because heterozygous sites are less likely to be shared across a subfamily as compared to within a single genus. The PPD pipeline generated both a list of putatively paralogous loci along with trimmed alignments where regions of suspected paralogy have been removed. The original scripts were written to run with the output for HybPiper v1.x, and a modified version was created to utilise the output from HybPiper v2.x.

#### 2.3.4. Orthology inference using the Yang & Smith pipeline



The Yang & Smith pipeline infers orthologs (and thus separates paralogs) from the output of target capture pipelines such as HybPiper and CAPTUS. Both the MO and RT methods of the Yang & Smith pipeline work by firstly rooting each gene tree with the outgroups, and next discarding trees with duplications in the outgroups, or that have non-monophyletic outgroups which are nestled within ingroup taxa. Finally, for trees which have passed the filter, the pipeline identifies and prunes the duplicated clades. The MO approach retains only the ortholog tree with the larger number of taxa, with the outgroups included. The RT approach retains all paralogs if they have enough taxa and treats them separately, exporting each without outgroup taxa (which can be added back later for species tree construction).

The original scripts were modified to run in Python 3. Apart from the change in Python version, and a minimum number of 10 taxa for both the MO and RT approaches, all other commands were run with the same parameters. The sample `Sind730_Cercis_canadensis_Rowland_sn` was indicated as the outgroup in the orthology inference step. The script `prune_paralogs_MO_1to1_MO.py` was run as part of the MO approach to first remove trees with non-monophyletic or duplicated outgroups prior to pruning the duplicated taxa from the trees, while for the RT approach the script `prune_paralogs_RT.py` was used to generate trees of each duplicated clade that met the minimum number of 10 taxa.
